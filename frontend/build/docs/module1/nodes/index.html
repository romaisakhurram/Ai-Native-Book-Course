Understanding ROS 2 Nodes

In ROS 2, a node is an executable process that performs computations. It's the fundamental building block of any ROS 2 system, representing a single logical unit of computation. Nodes can be thought of as individual programs or processes that work together to form a robotic application.

Key Characteristics of ROS 2 Nodes​

  1. Modularity: Each node is designed to do a specific task (e.g., controlling a motor, processing camera data, estimating robot pose). This modularity makes the system easier to develop, debug, and maintain.
  2. Concurrency: Multiple nodes can run concurrently, either on the same machine or distributed across different machines, communicating with each other.
  3. Independence: Nodes operate independently of each other. They don't need to know the internal workings of other nodes, only how to communicate with them via ROS 2 communication mechanisms.

Node Naming​

Every node in a ROS 2 graph must have a unique name. This name is used to identify the node and differentiate it from others. Node names can be assigned explicitly by the developer or automatically generated by ROS 2.

Examples of Node Names:

  • /camera_publisher
  • /odom_estimator
  • /robot_controller

Creating a ROS 2 Node (rclpy - Python)​

In rclpy (the Python client library for ROS 2), creating a node involves inheriting from the rclpy.node.Node class.

Here's a basic structure of a ROS 2 Python node:

import rclpy
from rclpy.node import Node

class MyCustomNode(Node):
    def __init__(self):
        # Call the base class constructor with the node name
        super().__init__('my_custom_node_name')
        self.get_logger().info('My custom node has been started!')
        # Further initialization (publishers, subscribers, timers, etc.) goes here

def main(args=None):
    # Initialize the rclpy library
    rclpy.init(args=args)

    # Create the node
    my_node = MyCustomNode()

    # Spin the node to keep it alive and allow callbacks to be processed
    rclpy.spin(my_node)

    # Destroy the node explicitly
    my_node.destroy_node()
    # Shutdown the rclpy library
    rclpy.shutdown()

if __name__ == '__main__':
    main()

Explanation:​

  • rclpy.init(args=args): This function initializes the rclpy client library, making it ready to communicate with the ROS 2 system. It must be called before any other rclpy functions.
  • super().__init__('my_custom_node_name'): The constructor of your node class calls the constructor of the base Node class, passing the unique name for your node.
  • rclpy.spin(my_node): This call keeps the node alive and listening for events (like incoming messages or timer expirations). It blocks until the node is shut down.
  • my_node.destroy_node(): Frees up all resources used by the node.
  • rclpy.shutdown(): Shuts down the rclpy client library.

Node Management​

ROS 2 provides command-line tools to interact with nodes:

  • ros2 run <package_name> <executable_name>: Launches a node.
  • ros2 node list: Lists all active nodes in the ROS 2 graph.
  • ros2 node info <node_name>: Displays detailed information about a specific node, including its publishers, subscribers, services, and actions.

Nodes are the foundation upon which complex robotic behaviors are built. Understanding how to create, name, and manage them is crucial for developing any ROS 2 application.
