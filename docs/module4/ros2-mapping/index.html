ROS 2 Action Mapping for VLA Systems

Introduction​

This chapter explains how high-level tasks generated by the LLM-based planning system are mapped to specific ROS 2 actions in Vision-Language-Action (VLA) systems. The action mapping component serves as the crucial bridge between cognitive planning and physical execution.

The Action Mapping Challenge​

Translating abstract, high-level goals into specific, executable robotic actions requires careful consideration of:

  1. Task Decomposition: Breaking complex goals into primitive actions
  2. Capability Matching: Ensuring planned actions match robot capabilities
  3. Parameter Translation: Converting conceptual parameters to ROS 2 message formats
  4. Execution Sequencing: Ordering actions appropriately for successful completion

Mapping Architecture​

The action mapping process follows this flow:

[LLM-Planned Task] → [Task Type Identification] → [Action Mapping] → [Parameter Translation] → [ROS 2 Action Execution]

Implementation Concepts​

The following pseudo-code demonstrates the mapping architecture:

def map_task_to_ros_action_function(task_description: dict) -> dict:
    """
    Maps high-level tasks from LLM planner to ROS 2 actions.
    
    Args:
        task_description: Dictionary describing the task from LLM planner
        
    Returns:
        Dictionary with ROS 2 action details
    """
    # Determine the appropriate ROS 2 action based on task type
    task_type = task_description.get('type', 'unknown')
    task_params = task_description.get('parameters', {})
    
    # Mapping of high-level task types to ROS 2 action types
    task_to_action_mapping = {
        'navigation': {
            'action_type': 'NavigateToPose',
            'package': 'nav2_msgs',
            'parameters': {
                'pose': task_params.get('target_pose', {}),
                'behavior_tree_id': task_params.get('behavior_tree', 'default_nav_tree')
            }
        },
        'manipulation': {
            'action_type': 'FollowJointTrajectory',
            'package': 'control_msgs',
            'parameters': {
                'trajectory': task_params.get('trajectory', {}),
                'joint_names': task_params.get('joint_names', [])
            }
        },
        'perception': {
            'action_type': 'FindObject',
            'package': 'vision_msgs',  # Conceptual package
            'parameters': {
                'target_object': task_params.get('object', ''),
                'search_area': task_params.get('search_area', {}),
                'timeout': task_params.get('timeout', 10.0)
            }
        }
    }
    
    # Return the mapped action details or a default
    return task_to_action_mapping.get(task_type, {
        'action_type': 'GeneralCommand',
        'package': 'std_msgs',
        'parameters': task_params
    })

Key Mapping Categories​

Navigation Actions​

  • High-level task: "Go to the kitchen"
  • Mapped action: NavigateToPose in nav2_msgs
  • Parameters: Target pose coordinates, navigation behavior tree

Manipulation Actions​

  • High-level task: "Pick up the red cup"
  • Mapped action: FollowJointTrajectory in control_msgs
  • Parameters: Joint positions, trajectory waypoints, gripper commands

Perception Actions​

  • High-level task: "Find the blue ball"
  • Mapped action: FindObject (conceptual)
  • Parameters: Object description, search area, timeout

System Design Principles​

The action mapping implementation follows several key principles:

  1. Abstraction Layer: Provides a clean interface between planning and execution
  2. Extensibility: Easy to add new action mappings as robot capabilities expand
  3. Error Handling: Graceful degradation when planned actions are not feasible
  4. Safety Integration: Validation of actions before execution

Integration with ROS 2 Ecosystem​

The mapping system integrates with the ROS 2 ecosystem through:

  • ActionLib: For long-running actions with feedback
  • Message Passing: Using standard ROS 2 message types
  • Service Calls: For synchronous operations
  • Parameter Server: For configuration of mapping behaviors

Parameter Translation​

The mapping process translates high-level parameters to ROS 2 formats:

  • Natural language objects → Specific ROS 2 object messages
  • Human locations → Coordinate frames and poses
  • Task requirements → Action goal parameters

Example Mapping Scenario​

A complete example of the mapping process:

  1. High-level goal: "Go to the kitchen and bring me a cup"
  2. LLM decomposition: Navigate → Find object → Grasp → Navigate → Deliver
  3. Action mapping:
    • Navigate → NavigateToPose with kitchen coordinates
    • Find object → FindObject with "cup" descriptor
    • Grasp → FollowJointTrajectory with grasping trajectory
    • Navigate → NavigateToPose with return coordinates
    • Deliver → FollowJointTrajectory with placing trajectory

Error Handling and Validation​

The system includes validation at multiple levels:

  • Capability validation: Ensuring the robot can perform planned actions
  • Parameter validation: Checking that parameters are within feasible ranges
  • Safety validation: Ensuring actions won't result in harmful behavior
  • Context validation: Verifying environment state before action execution

Summary​

The ROS 2 action mapping component is essential for translating the abstract plans generated by the LLM-based system into concrete actions the robot can execute. This mapping focuses on system design principles rather than specific tooling, ensuring the concepts remain relevant as technology evolves. The approach emphasizes modularity, safety, and extensibility to accommodate future capabilities while maintaining compatibility with the ROS 2 ecosystem.
